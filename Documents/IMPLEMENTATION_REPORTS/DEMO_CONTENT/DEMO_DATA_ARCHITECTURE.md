# LEGALIR v1.0.0 — Demo Dataset Architecture

## Goal

Provide a coherent, deterministic demo dataset for the three content sections —
**اسناد من (My Documents)**, **قراردادهای من (My Contracts)** and **حافظه (Memory)** —
anchored to a single persona: **امیر رضایی**, manager of
**شرکت خدمات فنی و مهندسی رهام پارس**.

## Persona

| Field | Value |
|-------|-------|
| نمایش نام | امیر رضایی |

| شهر / استان | تهران |

| نوع کاربر | business |

## Storage model (Path A)

Demo content is persisted to the same JSON file database used by the rest of the
product (`.data/*.json`), and served through real Next.js App-Router route
handlers — consistent with the earlier migration of legal-library, blog and
rewards onto JSON DB + API routes.

### Tables (files)

| File | Shape | Notes |
|------|-------|-------|
| `.data/documents.json` | `V1DocumentDetail[]` | 6 documents |
| `.data/contracts.json` | `V1ContractDetail[]` | 5 contracts |
| `.data/memories.json` | `V1MemoryItem[]` | 7 memories |
| `.data/relationships.json` | `DemoRelationship[]` | 7 cross-resource links |
| `.data/conversations.json` | `DemoConversation[]` | 2 linked conversations |
| `.data/conversation-messages.json` | `Record<conversationId, msgs[]>` | merged idempotently |
| `.data/demo_meta.json` | `DemoMeta` | idempotency guard |

### Identity tables (mutated in place, never clobbered)

`seedDemoContent` also aligns the demo user's *identity* (displayName, email,
100% profile, active Gold subscription) so the persona is coherent when the
demo user already exists in `users.json`.

## Seeding

- **Deterministic**: every row id is fixed (`doc-emp-001`, `cnt-emp-001`,
  `mem-001`, `rel-001`, `conv-demo-001`, …).
- **Idempotent**: guarded by `.data/demo_meta.json` whose `version` must equal
  `DEMO_SEED_VERSION` (`"legalir-demo-v3"`) and `userId` must match. On
  mismatch the tables are re-written atomically (documents/contracts/memories/
  relationships are replaced; conversations are append-merged by id).
- **Trigger**: `db.ts` runs `seedDevData()` then
  `seedDemoContent(findUserByMobile(DEMO_USER_MOBILE)?.id)` in development.

## API surface

All endpoints are cookie-authenticated (`legalir-session`) via the shared
`src/lib/api/server-auth.ts` helper.

| Method | Route | Returns |
|--------|-------|---------|
| GET | `/api/v1/documents` | `V1DocumentListResponse` (search/status/sort/page) |
| GET | `/api/v1/documents/[id]` | `V1DocumentDetail` |
| GET | `/api/v1/documents/[id]/analysis` | `V1DocumentAnalysisResponse` |
| GET | `/api/v1/documents/[id]/download` | PDF `application/pdf` (attachment) |
| DELETE | `/api/v1/documents/[id]` | `{ deleted: true }` |
| GET | `/api/v1/contracts` | `V1ContractListResponse` (search/state/category/sort/page) |
| GET | `/api/v1/contracts/[id]` | `V1ContractDetail` |
| GET | `/api/v1/contracts/[id]/versions` | `V1ContractVersionDetail[]` |
| GET | `/api/v1/contracts/[id]/analysis` | `V1ContractRiskAnalysis` |
| GET | `/api/v1/memories` | `V1MemoryListResponse` (`memoryEnabled` from preferences) |
| PATCH | `/api/v1/memories/[id]` | `V1MemoryItem` |
| DELETE | `/api/v1/memories/[id]` | `{ deleted: true }` |

## Client integration

The existing client functions in `src/lib/api/v1.ts` (`fetchDocuments`,
`fetchContract`, `fetchMemories`, …) and their React Query hooks
(`useDocuments`, `useContracts`, `usePhase11`) consume these routes unchanged —
their URLs already match.

## PDF fixtures

Three real, multi-page Persian RTL PDFs are generated by
`apps/frontend/scripts/generate-demo-pdfs.mjs` (pdf-lib + @pdf-lib/fontkit +
Vazirmatn) into `apps/frontend/public/demo-documents/`:

1. `قرارداد-کار-و-تعهدات-بیمه.pdf` — 4 pages (employment contract)
2. `توافقنامه-محرمانگی-NDA.pdf` — 2 pages
3. `قرارداد-پیمانکاری-خدمات-فنی.pdf` — 2 pages

Documents reference them via `previewUrl` (`/demo-documents/…`) and the download
route streams them back with `Content-Disposition: attachment`.
